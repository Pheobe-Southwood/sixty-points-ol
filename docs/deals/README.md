# 牌局故事（`docs/deals/`）

这个目录放**作者编排出来的牌局**：从 `/studio` 导出的 JSON，一个 slug 一个文件。
下游「规则演示」页读它们，把作者的原话与引擎算出的牌面拼成一步一步的讲解。

## 怎么产出一份

1. 打开 `/studio`（不在任何菜单里，直接输 URL；线上也能开，草稿只存在你自己的浏览器里）。
2. 填 **标题 / 种子 / 三家级别 / 发牌人** → 「发牌，开始编排」。
   - 种子决定牌面：同一个种子 + 同样的三家级别 + 同样的发牌人 = 同一副牌。
   - 级别默认 `5(+0)`，这样级牌就是 5，与教程里那些「♣3-4-6 是顺子」的例子同一个将牌环境；任何级别都能用。
3. **三家都由你出**：叫牌 → 埋底 → 每一墩。牌面点选，合法性由引擎判定（不合法就出不去，并告诉你为什么）。
4. **每一步旁边写说明**（「为什么这样打」）。可选的还有：每墩小结、开篇、收尾。
   - 牌面、赢家、墩分、张数、结算都是引擎现算的灰色标签，不用你写，也不该你写。
5. 想改就改：`撤销` / `重做` / 某一步的「重打」（丢掉该步及其之后，可撤销）/ 「换种子重开」。
6. 「复制 JSON」或「下载 `<slug>.json`」，把文件放到这个目录（`docs/deals/<slug>.json`）交给我。

没打完也能导出，但只能当草稿备份 —— 演示页只接受打完的（`complete: true`）。

## 我拿到之后做什么

1. 跑 `pnpm --filter web deal`（`apps/web/scripts/build-deal-stories.ts`）：结构校验 → 回放校验 →
   断言存下来的牌面与回放逐项一致 → 合并讲解 → 生成 `apps/web/src/lib/tutorial/stories/<slug>.ts`
   （页面渲染用的数据，含索引 `stories/index.ts`）→ 生成 `docs/deals/<slug>.review.md`。
   任何一条不过就**非零退出并列出全部问题**，绝不写半个文件。
2. **你的原话逐字保留在 `<slug>.json` 里，永不改写。** 我的改动全放在 `notes/<slug>.json`。
3. 逐条列出改动：`<slug>.review.md`（原文 → 现在的话 → 为什么），供你复核。
4. `pnpm --filter web deal:check` 只校验不写：仓库里的生成物必须等于**现场重算**的结果
   （手改生成物、或改完 JSON/notes 忘了重跑，都会红）。

## 讲解的三个来源（`notes/<slug>.json`）

| 来源 | 含义 | 放在哪 | 页面上 |
| --- | --- | --- | --- |
| `author` | 你写的原话 | `<slug>.json` 的 `actions[].note` | 原样显示 |
| `polish` / `clarify` | 我只动字句、或按引擎事实改写（必须记 `original` 与 `why`） | `notes/<slug>.json` 的 `steps` | 显示改后的，末屏可展开看原文 |
| `fill` | 原本没写、我补的 | 同上 | 与你的话同一样式（读起来是一个人讲的） |

`steps` 的键是**动作下标（0 起）**，与 `actions` 数组一致；界面上的步号是它 +1。
`trickNotes` 的键是墩号（0 起）。这两处都会被 `deal:check` 校验：键越界、润色条目的 `original`
与当前原话对不上、或者该有说明的步（出牌 / 埋底 / 非「不叫」的叫品 / 发牌）缺话，都会直接报错。

## 补写的语气（从已有原话里提炼，写新的缺口时照着来）

- **短句、口语、常省主语**：用「自己 / 队友 / 另一家 / 庄家 / 闲家」，不写「我方座位 0」，也不写
  「根据结构优先原则」这种教科书腔；改用「必出」「只有这一手」「随意出」「管上」「垫分」「清主」「反攻」。
- **牌一律带字形**：`♣J-Q-K-A`、`♥5-6-7`、`♦3-5-6`、`小王`；不写裸花色字母（界面守卫禁止 `40 C` 这种写法）。
- **可以带一句人味**：他写过「冲动是魔鬼」「漂亮的攻势！」「埋分有风险，叫牌需谨慎」，这种照写。
- **规则解释就地给**：像「2-3-5 是三顺（4 为级牌跳过），必出」那样，把依赖级牌的前提写进句子里。
- **每条补写都要能对回引擎事实**：这一手为什么非得这样出（结构优先的实际分解）、谁赢、这墩多少分、
  自己还剩几张主、外面还剩几张。不替牌手评价牌的好坏，除非是复盘语气。

## JSON 字段（`version: 1`）

| 字段 | 说明 |
| --- | --- |
| `slug` / `title` | 文件名与深链；这一副讲什么 |
| `names` | 三个座位的代称（默认 `你 / 阿豪 / 小美`，界面上一律用名字，不出现方位） |
| `spec` | 种子↔牌局的对应关系：`{ seed, dealerSeat, levels }` |
| `deal` | 冗余存证：`hands`（发牌时各家 17 张）、`originalKitty`、`kitty`（埋底后的 3 张）、`trump`、`contract`、`summary` |
| `actions` | 动作序列，按序回放即得这副牌；每条带 `note`。`deal` / `bid` / `bury` / `play` 四种，牌用牌键（`H5` / `j1`） |
| `trickNotes` | 与「已完成的墩」一一对应的小结（可空） |
| `intro` / `outro` | 开篇与收尾（可空） |
| `complete` | 是否打完；`false` 的只能当草稿备份 |
| `exportedAt` | 导出时间 |

`deal` 块是**存证而不是推导结果**：页面渲染读它，不靠种子重算。所以引擎或随机数实现将来变了，
已发布的讲解也不会跟着变 —— 转换脚本会把两者对一遍，一旦不一致就直接失败。
