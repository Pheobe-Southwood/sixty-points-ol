# 机器人参数面与参数竞技场：把「哪套打法更强」变成可复算的数字

**这是对 ADR-0015 两处的正面修订**：一是「刻意没有难度梯度／只有一档」——现在口径收进一份显式参数
（`BotParams`），出厂默认仍是一档，但**同一份策略可以被摆成多档去比较**；二是那条「这是陪练观感 +
有据可依的取向，不是 EV 最优声明」——现在有一个**同副牌配对竞技场**（`packages/bot/src/arena.ts`），
取向可以量、也必须量。本 ADR 同时记下这一轮量出来的结论，以及**依证据改掉的默认值**。

## 为什么要动

上一轮对真实牌局的复盘（`data/_analysis/` 下的非正式脚本）指出三件事：叫牌太保守、防守方该不该杀/该不该垫分
没有依据、以及**策略包里根本没有「同伴」这个概念**（`grep` 不到 partner/队友/sameSide，`wantWin` 只看
墩上已有的分）。复盘能指出可疑点，但撑不起结论：那批牌只有 7 桌 16 副，而且「庄家平均 9.3 张主牌 vs 闲家 4.4 张」
说明**人类拿到的是强牌**，样本本身有选择偏差。要回答「换个打法是不是更强」，需要一个能把**同一副牌**
喂给两套参数的台子。

## 决定

### 1. 参数是策略签名的一部分，不是运行期配置

`BotParams` 的每一项都对应一处曾经写死的常量，`BASELINE_PARAMS` 逐一取历史值。因此：

- **不传参数 = 历史行为逐字节不变**（`test/arena.test.ts` 用「不传 vs 显式基线打完整局逐字节相同」钉死）；
- 参数只是纯函数的入参 —— 无 IO、无 RNG、无隐藏状态，同一视图 + 同一参数永远同一动作（纯度守卫照旧扫 `src/`）；
- 线上调用点（`apps/web` 的调度器、`simulateDeal`）继续两参调用，**行为由默认值定义**，将来调参不必改调用方。

明确**不做**：把参数暴露成环境变量或数据库配置。它不是配置项 —— 机器人必须可复现，
而「同一局面同一动作」这条承诺要成立，参数就只能从调用方进、且是纯输入。

### 2. 同伴概念：只取可证的终局，而且分成两个开关

闲家的同伴由**公开信息**推出（`deal.contract.declarerSeat` 与自己的座位，`partnerSeatOf`），
庄家恒为 `null`。只在我**是第三家**（`trick.plays.length === 2`）时做同伴决策 —— 那一刻当前赢家
就是本墩终局，后面没人能翻案；第二家时同伴的赢墩还没定，让利与喂分都可能送给庄家，所以一概不做。

- `partnerAware`：同伴已定的赢墩上不抢、也不为它花主牌（能垫非主牌就垫）;
- `feedPartner`：同伴已定的赢墩上把分垫给同伴。

依据是引擎的结算公式（`scoreDeal`）：`finalScore` 只算**庄家**抓到的分与底牌，闲家抓到的分**永远不进这个式子**，
只起「不让庄家拿到」的作用。所以在本墩归属已定时，把分垫给同伴 = 把分从庄家的账上拿掉。

分成两个开关是因为它们不是一件事：「不抢」是省钱，「喂分」是转移分的归属。
竞技场的读数是**这一对**（`partnerAware + feedPartner` = +0.057 级/座位/副，两个配比各 2000 种子）
有支撑，而单独开 `partnerAware` 与 0 不可区分（+0.0038，CI 跨 0）—— 也就是说收益无法单独归因到「不抢」那一半。
两个都进默认，是因为被量的是这一对，且「不抢」在逻辑上让喂分规则自洽（否则你会一边把分喂给同伴、
一边又把那一墩抢回来）。

### 3. 竞技场是唯一认可的对比方法

- **同一种子 = 同一副牌**：`rngFactory` 只取决于种子，与 cell 无关，所以两侧拿到的牌完全一样；
  只改打牌参数时连合同与将牌都不变（`test/arena.test.ts` 钉死）。
- **座位轮换**：把两侧参数整体转着放三圈再取平均，座位与角色的系统性偏差因此被抵消 ——
  这也正是「1 变体 + 2 基线」与「2 变体 + 1 基线」（2:1 / 1:2）能用同一套数说清楚的原因。
- **独立单位是种子**：同一颗种子的三圈是聚类的，所以先按种子取平均，再做聚类 bootstrap 区间与
  符号翻转置换检验；多细胞比较过 Holm–Bonferroni（家族只算真变体，A/A 不占名额）。
- **A/A 恒 0**：两侧同配置时逐种子的配对差**均值**必须恒等于 0。这是估计量无偏 + 轮换没偷换牌的证明，
  不是「跑出来差不多」。
- 读数：单副台用「每座位每副升级数」，整局台用「每座位终局进度」与「谁先打完」。

## 量出来的结论（单副台 2000 种子 × 3 轮换，两个配比各一遍；整局台 100 种子 × 3 轮换 + 5000 起的复现批次）

单位：单副台 = 每座位每副升级数；整局台 = 每座位终局进度。括号内是两个配比各自的结果。

| 变体 | 单副台 | 整局台 | 判定 |
|---|---|---|---|
| 竞叫阶梯原点 12→6（开叫门槛不动） | **+0.282 / +0.271** | **+14.3** | 采纳（唯一过「幅度」门槛的一项） |
| 领地余量 {2,5}→{1,2} | +0.037 / +0.035 | +1.6 / +0.9 | 采纳（第二梯队，见下） |
| 同伴概念（不抢 + 喂分） | +0.057 / +0.058 | +1.1 / +0.9 | 采纳（第二梯队） |
| 垫牌分权重 30→0 | +0.016 / +0.013 | +0.8 | **不采纳**（唯一被幅度门槛挡住 + 机制说不清） |

事前的采纳门槛是四条（机制计数非零、CI 不含 0、Holm 校正后显著、**幅度 ≥ +0.1 级/座位**，且整局台不为负）。
只有**竞叫阶梯**那一条过了幅度门槛（+0.27，是三倍余量）。领地余量与同伴概念**没过幅度门槛**
（+0.037 / +0.057），仍然被采纳 —— 理由是它们各自在两个配比、2000 种子下都显著，机制计数证明开关真的接线，
整局台同向为正，而且它们是「打得更对」这一类不会互相冲突的改动；把它们否掉等于丢掉已量到、也解释得清的收益。
这是**一次有意偏离事先门槛的决定**，所以记在这里：若将来要收缩参数面，先砍的是这两项，而不是阶梯。
垫牌分权重则被门槛挡住**且**机制说不清（见下），所以不采纳 —— 事先门槛就该在这时候起作用。

### 3 条值得单独记的机制

1. **收益的大头是「庄家位」，不是「打得好」。** 把 500 种子的组合拆开：
   变体做庄的副 Δ = **+1.59**，基线做庄的副 Δ = **−1.02**。也就是说，同一副牌上
   「谁坐庄」几乎决定了升级归属 —— 因为升级表把主要级数给了庄家侧
   （打成 1–5+ 级、闲家只在庄家打输时按 `ceil(差/10)` 升级）。所以「愿意一路用最小步长把价抬上去把庄家位拿过来」
   是巨大的正收益，而**跳叫**（同一件事做过头，白抬及格线）是负的：+++ 两者一起解释了
   `bidLadder` 强正、`bidJump` 弱负这个看上去矛盾的组合。

2. **上一轮的那个结论被推翻了。** 复盘认为「拿到牌就出大王」是错的（举证 T5d3 的底牌 25×2、T2d2 的底牌 10×1
   都是庄家保底）。竞技场说：把大王留到末轮 **−0.096 级/座位/副**，显著更差。
   两个读数并不矛盾 —— 复盘看的是两副具体牌（而且那两副的末轮闲家本来就赢不了），
   台子看的是 6000 副的平均。教训写在这里：**个案研究只能用来提出假设，不能用来定策略。**

3. **垫牌分权重这条被门槛挡住了，而且说不清。** 它四次单副台读数全为正
   （+0.0183 / +0.0153 / +0.0162 / +0.0130），整局台 +0.81（Holm 未过）。但幅度只有 +0.016，只有门槛的六分之一；
   更要紧的是**机制对不上**：它实际改变的是「5/10 这类分牌与相邻低张谁先垫」的次序
   （`level*2` 项在不计分时反超），而 `pointsToDeclarerPoints` 几乎不动（0.98–0.99×）——
   也就是说它**并没有真的少送分给庄家**。一个「读数为正但做的事不是它看起来该做的事」的开关不进默认。

顺带一条方法论教训：**轮换必须是 3 的倍数**。座位偏差靠「每个座位都当过一次变体」抵消，
少转一圈就有座位永远坐不到变体那侧，A/A 也不再恒为 0（`rotations=2` 时是 −0.006）。
`scripts/arena.ts` 现在会在轮换不是 3 的倍数时告警；同理，**晋升之后**「变体参数 = 当前基线」的细胞
会给出 Δ=0、p=1 而不是报错，所以 CLI 会把这种细胞显式标成**空转** —— 我确实踩过这个坑
（晋升之后重跑同一批变体，7 个细胞里有 6 个静默变成了空转）。

## 后果

- `BASELINE_PARAMS` 改了三项默认值：`bidLadderBase 12→6`、`leadCaution {2,5}→{1,2}`、
  `partnerAware/feedPartner false→true`（`discardPointWeight` **不动**，理由见上）。
  被钉死的测试随之更新：`willingPoints` 的阶梯表（`policy.test.ts`）、`fullgame.test.ts` 的开叫率 / 重发率注释，
  并新增一条「默认参数就是量出来的那一套」的用例 —— 没有它，把 `bidLadderBase` 改回 12
  只会让「基线等价」那条测试照样绿（它测的是「不传 = 显式传默认」，对默认值本身不敏感）。
- **机器重演（ADR-0016）是快照**：已经落库的重演记录保持原样（那正是快照的语义），但同样一副牌
  在参数变了之后重算会给出不同结果。这不是 bug，是「策略是版本化输入」的直接后果。
- **陪练体感要如实说一句**：2 变体 + 1 基线那一档里，两个新默认机器人拿走了 **93.5%** 的冠军份额
  （公平份额 66.7%），独苗基线座位只剩不到 7%；1 变体 + 2 基线下是 73.8%（公平 33.3%）。
  也就是说一个人类席位面对两个新默认机器人时，坐庄机会大约从 1/3 掉到 1/6，赢面也大幅缩水。
  这是「更强」的代价，写在 README/CONTEXT 能看见的地方，想练叫牌就把 `bidLadderBase` 抬回去
  （它是实验里唯一一根「强度旋钮」，其余两项都不改变争庄的态势）。
- `scripts/arena.ts`（CLI）**不进 CI**：统计不是门槛，进了只会让 CI 变慢且更易假红。
  进 CI 的是 `test/arena.test.ts` 那几条不变量（等价、确定性、A/A 恒 0、严格配对、功效非空转、开关接线、
  默认值就是量出来的那一套），以及 `test/policy.test.ts` 里**每个开关一个固定局面**的用例 ——
  每条都同时钉「默认怎么做」与「拨动之后确实变了」，所以开关一旦没接线就会红
  （用注入法验过：把「不抢同伴已得赢墩」那一半短路掉，用例立刻失败，还原后逐字节一致）。
- 变体目录里的 `legacy-baseline` 显式写下了晋升前的全部值 —— 晋升之后 `undefined` 就是新默认，
  没有它，「这轮到底改了多少」就再也量不出来了。
- `scripts/arena.ts` 另有一个 `--baseline <变体名>`：把**配置 0** 指定成任意变体，
  于是「任意 A vs B」都能量（之前 `undefined` 只能当其中一侧，量不出「晋升前后」与「候选 vs 当前默认」）。

## 后续：叫牌精调（曲线画完了，默认没动）

晋升时 `bidLadderBase` 只量过 6 与 12 两个点就把 6 提为默认 —— 等于在一条没画过的曲线上取一个点当最优。
补扫之后的结论（细节与数字见 `docs/bot-arena-report.md` §7）：

- **曲线是单峰，峰值在阶梯原点 8**，6 就在峰值旁边：8 比 6 好 +0.021/+0.030（2:1 时 Holm 显著）。
  更凶的一侧掉得很快（0 → −0.12，做庄打成率从 65% 掉到 54%）——§3.1 那条机制的**边界**被量出来了。
- **开叫门槛与竞叫阶梯有交互**，不能各自调：旧阶梯下把门槛降到 6 是负的，新阶梯下降到 8–11 是正的。
  另外门槛 8 把全 pass 重发从每 18000 座位-副 354 次压到 32 次（ADR-0015 调门槛的原始动机）。
- 最优是一块**平台**（阶梯 8 × 门槛 8–11，约 +0.05~0.06），换一批没参与调参的种子复现一致到 ±0.005
  ⇒ 不是过拟合。
- **但不采纳**：幅度只有 +0.052~+0.066（事先门槛是 ≥ +0.1，只有六成），而且整局台测不出显著
  （1:2 时 +0.57/+0.64，CI 跨 0；Holm 一个都过不了；冠军份额与公平份额齐平）。
  这与上面那次「有意偏离门槛」不同：那次是显著 + 机制清楚 + 整局台同向，这次是在阈值以内、
  整局台看不见的同类旋钮细调，而收益只有原晋升的五分之一 —— 在平台上继续抠就是追噪声。
- **`maxWilling` 是惰性字段**：85→95 的 Δ 恰好 0.0000（两个配比、各 6000 副），实践中永远够不到这个封顶。
- **一条方法教训**：「竞叫次数」这类**过程计数**不能当强度的证据。精调候选的竞叫次数是默认的 0.97×，
  但它改成用**开叫**去拿庄家位（开叫 ×1.38），按同一参照物量它其实抢得更多
  （1 个座位对两个历史基线：55.2% vs 默认的 51.0%）。机制计数只用来证明开关接线，不用来论断强弱。
