# MCP 无身份会话：只放行 read_rules 与 claim，凭据只交给人

ADR-0010 写道「MCP 侧**不提供自注册**：那会平白多出一个『免费造身份/抢名字』的入口，而现有
`register(name)` 在名字已存在时会返回那条已有 user 行（含令牌）」。**那条理由已经被 ADR-0009 修掉**：
`auth.ts` 的 `createIdentity` 撞名一律返回 `null`，`claim` 路由撞名 400。于是当时的结论失去了依据，
而「AI 帮人类把身份配起来」这条路一直缺一个入口 —— 宿主没配凭据时，工具面连读规则都做不到
（stdio 当场以非 0 退出，`/api/mcp` 直接 401）。

## 决策

1. **凭据是可选的**，两种传输都认「没带凭据」为一种**合法**状态（**无身份会话**）：
   stdio 缺 `SIXTY_CREDENTIAL` 不再退出，`/api/mcp` 缺 `Authorization` 不再 401。
   没带凭据时**只放行两个工具**：`read_rules`（纯本地读引擎里的说明文本，本来就不碰服务器）
   与 `claim`（新建身份并把**凭据串**交给人类）。其余工具一律回一句指路错误。
2. **「需要身份」从传输层挪到工具层，并且默认拒绝。** 工具表对所有会话**一视同仁地全列**
   （模型要看得见配好凭据之后会拿到什么，宿主也才不会以为这台服务器只有一个工具），
   而 `callTool` 在调 `GameApi` 之前按 `requiresIdentity` 拦下 —— 新工具**不写这个标志就是要身份**，
   所以「忘了声明」的默认后果是更严而不是更松。
3. **凭据只交给人，本会话不接管。** `claim` 返回 `{name, credential, note}` 就结束：
   - `/api/mcp` 是**无状态**的（ADR-0010），请求之间没有地方存这个身份；
   - stdio 当场接管会让 agent 与人类**共用同一串凭据**（README 的「一个座位一个凭据」：两边会互相
     抢着出牌），而那正是人类要拿去导入浏览器的东西；
   - 于是人类拿着这串去大厅「粘贴凭据串」导入（或填进他自己的 MCP 配置）后重连，才谈得上使用。
   工具面因此不是一个**自足的身份磨坊**：它能把身份**交出去**，但不能借此自己变成另一个人。
4. **没带凭据 ≠ 凭据无效。** 带了（cookie 或 `Authorization: Bearer`，非空）却解析不出身份时一律
   401，**绝不静默降级**成无身份会话 —— 否则「凭据串粘错/已失效」在模型看来会变成「权限突然全没了」，
   而它还会照着无身份那份说明去 claim 一个新身份，把问题掩盖成一次莫名其妙的换人。
5. **不给 claim 加闸**（没有开关、没有限流）：名字唯一是唯一约束，与浏览器那条
   `POST /api/auth/claim`（今天就是公开、无限速、无验证码的）**完全同形**。在单实例进程里加一张
   限流表要引入新的存活期与服务端状态 —— ADR-0012 已经用同一理由拒过一个定时器。
   这一点是**知情接受**：风险形状是名字先占与 `users` 表无界增长，**不**包含接管别人的身份。

## 后果

- **工具面 schema 多付 855 字符**（13 → 16 个工具），`SCHEMA_LIMIT` 抬到 5,650、
  `CUMULATIVE_LIMIT` 同步 +18,000（见 ADR-0011 的那条后续）。其中 `claim` 是**给还没有身份的人**用的：
  已配好凭据的连接也看得见它（清单不按凭据筛），代价是每个打牌的 agent 每回合多付约 340 字符。
- **未鉴权入口多了一条可达路径**，但不多一种能力：任何 MCP 宿主现在都能驱动浏览器里那个
  「创建身份」按钮的同一件事。`read_rules` 那条连服务器都不碰。
- `claim` 撞名的原话直接转达（`服务器拒绝：这个名字已被使用…`），且响应里**不出现凭据** ——
  ADR-0009 的口子（输入别人的名字就等于接管他的座位与手牌）在这条新路上同样堵死。
- 座位工具是同一批落地内容，但**不是**本 ADR 的决策：`leave_seat` / `take_seat` 只是把浏览器已有的
  `DELETE|POST /api/tables/[code]/seat` 补到工具面（详见 CONTEXT.md 的 **离座 / 补位**）。
  它们在类型上刻意**不是** `SeatlessAction`：座位是同桌成员关系，不是引擎动作。

## 守卫

- `packages/mcp/test/tools.test.ts` 的**白名单断言**：`requiresIdentity === false` 的工具必须
  **恰好**是 `read_rules` 与 `claim`（写死字面量，不从表里推导 —— 从表里推导就是同义反复）。
  这是本次改动里唯一会让未鉴权会话多做一件事的编辑，所以它必须有警报；
  按 AGENTS 规则 9 做过「注入违规 → 变红 → 逐字节还原（sha256 比对）」。
- 同文件的会话行为断言：无身份时 `get_state`/`play`/`create_table` 一律指路且**不碰取数出口**；
  `claim` 透传名字、返回凭据串、撞名原话转达；`http-api.test.ts` 另钉「没凭据就不发
  `Authorization` 头」与「claim 的失败文案不是『先去看局面』（它没有局面可核对）」。
- `packages/mcp/scripts/mcp-check.ts` 对**真服务器**、两条传输各一次：不带凭据也能 list 到全集、
  `read_rules` 可用、`get_state` 指路、`claim` 出来的凭据**真的能用**、同名再 claim 必失败且响应无凭据；
  以及**坏凭据 401 与「没带凭据」200 的对照**（少了对照组，那条 401 也可能只是「这台服务器不收匿名请求」）。
