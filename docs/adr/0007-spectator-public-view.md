# 观战者只消费公共视图

一张同桌只有 3 个座位，但可以有任意多名 **观战者**：满座时用邀请链接进来的人、或主动 **离座** 的人。服务器给观战者的是 **公共视图** —— 手牌张数、已打出的牌与赢下的墩、定约与将牌、已抓分，以及结算后的底牌；**任何手牌与结算前的底牌都不进入这个负载**（`packages/engine/src/view.ts` 的 `publicView`，观战者拿到的就是它，不含 `you`）。

理由：邀请链接可以随手转发、观战者无法审核，所以「观战者能看到三家手牌」等于给任何拿到链接的人（以及他语音那头的玩家）开了上帝视角，这个泄漏面无法防守。公共视图与个人视图同源（`personalView = publicView + you`），隐藏信息从一开始就不在负载里，而不是在客户端被遮住（ADR-0002）。

后果：观战没有「上帝视角」用途，复盘只能看结算与战报。观战关系只是「这个人不坐这张桌的座位」的一条记录（`spectators` 表），唯一作用是让同桌页不再把他自动塞回座位；牌桌上的「N 人观战」徽标取的是**实时连接数**，与这条记录不是一回事。观战沿用既有通道（每连接一条 SSE + POST 动作），不升级到 WebSocket —— 这正是 ADR-0001 预留的那个评估点。
