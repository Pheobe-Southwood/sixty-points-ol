# 机器人座位：无令牌特殊身份 + 进程内代打

**这是对既有决策的正面修订**：ADR-0010 的「不做」里写着「仓库不提供自动打牌策略」，
README 把「机器人补位」列在 v1 范围外，CONTEXT.md 的词表也刻意没有「机器人 / 代理席位」这种角色。
现在要做的**凑桌陪练**（人不够 3 个时用机器人补空座）正是那条被否掉的东西，所以先记录为什么改主意。

动机有两条。一是**陪练**：这张桌只有凑够 3 人才能开局，一个人想练手就得先求两个人进群；
二是**测试**：端到端与冒烟测试此前必须自己操纵三个身份逐个出牌，有了机器人座位，
「1 人 + 2 机器人」就成了不用脚本操纵的对手，`pnpm bot-check` 与 CI 都靠它。

做法与 ADR-0010 给 LLM 席位定的规矩一致 —— **不新增角色，只多一种身份**：

- **机器人是一个无令牌的特殊身份**（`users.is_bot`）。它照旧住在**座位**上（级别与手牌按座位存，见 ADR-0009），
  但令牌从不外发，且 `findByCredential` / `findByToken` 一律排除 `is_bot` 行 ——
  于是「冒充机器人」「接管机器人座位」结构上做不到，机器人也不可能被改名。
  移出机器人时连身份一起删（名字回到可用池），所以「+机器人」不会把名字池越用越脏。
- **一桌至多 2 个机器人**：至少留一个人类座位，否则没人能按「开下一副」——
  机器人从不发起 `deal` / `newGame`，桌面级动作始终是人的事。
  在座的人类（不是观战者）随时可加/踢；只占空座，进行中加入即**补位**（继承该座位的手牌与级别），
  移出即**离座**语义（本副停在空座上等补位）。
- **策略在 `packages/bot`：纯函数，输入只有个人视图**（`PublicView` + `PlayerSeat`），
  输出一个**不带座位号**的动作。零 IO、确定性、无 RNG —— 同一局面永远同一动作，
  于是表驱动单测与整局回放都成立。它只做基线规则式启发，不做模拟搜索。
- **信息面与动作面各只有一条路**，与浏览器 / MCP 完全同源：看走 `viewFor`（同一份投影），
  动走 `applyTableAction`（同一条服务器权威路径）。策略拿不到完整 `GameState`，
  这不是纪律问题，而是它的签名里没有那个东西；`apps/web/test/bot-guard.test.ts` 把这条静态钉死
  （驱动器与路由不许出现 `getGameState` / `dispatch` / `personalView`，import 白名单写死）。
  记牌只数公共信息（已完成的墩、已抓分、手牌张数），底牌 3 张永远算作「未见的威胁」。
- **调度不依赖内存队列**：每次状态变更后重判一轮（幂等：没轮到就什么都不排），
  加上服务启动时 `hooks.server.ts` 全量补扫 —— 重启前停在机器人回合上的牌局会自动续打，
  而不是等人来推一下。每个动作前留 0.5–1.5 秒拟人延迟（环境变量可调零，测试与 CI 用它换确定性）。
- **在线点如实**：机器人没发请求，所以调度器只看不记（`viewFor` 是纯读）；
  它自己的动作经 `applyTableAction` 记一笔活跃，所以打牌时亮、停手一个窗口后转灰。

被否的替代：**纯 MCP 客户端 bot**（复用现成工具面上桌，服务器零改动）——
但没人跑那个进程时座位照旧空着，凑不了桌，与动机相悖；
**座位级 bot 标记**（`seats` 表加列）——`tableView` 的 JOIN 与 `SeatInfo` 无线形状都要重写，
而身份本来就是这个仓库里「谁坐在这」的正确答案；
**真身份 + 服务端保管令牌**——令牌一漏就是免费冒名；
**带蒙特卡洛模拟**——强度高一个量级，但不可复现（要注入 RNG）且远超第一版所需。

后果：`users` 表加列（老库靠 pragma 探测 + `ALTER TABLE` 迁移，`CREATE TABLE` 只对新库生效）；
`SeatInfo` 加 `bot: boolean`（wire 形状变更，`packages/mcp/src/wire.ts` 与 `SEAT_FIELDS` 同步，
`mcp-check` 的形状守卫会核）；ADR-0010 那条「不做」就此修订（LLM 宿主仍然自带策略，
但 `packages/bot` 现在可以作为参考策略被复用）；调度器活在单实例进程内，与 ADR-0001 的前提一致 ——
要横向扩展得先把「谁在替机器人想」这件事挪出进程。
