# 断开即离线：连接注销时作废「最近活跃」

「在线」= **有 SSE 订阅 或 最近 60 秒有请求**（ADR-0010）。这两半叠在一起，于是**真的断了**的时候，
那张脸上写着「在线」的座位卡还要再绿最多一分钟 —— 因为刚走的人必然刚活跃过，窗口还亮着。

实测（探针见 `probes/human-offline-detection.probe.mjs`，对构建产物 + 真服务端）：

| 情形 | 服务端何时注销连接 | 屏幕上那颗点何时变灰 |
| --- | --- | --- |
| 关标签页（t=2s 断，此后无任何请求） | 立即 | **60.2s** —— 也就是断开后约 58 秒 |
| 关标签页，但连接先安静了 60 秒 | 立即（≤200ms 采样粒度） | 立即 |
| 客户端卡死 / 休眠 / 拔网线（TCP 还活着，对端不读不回） | 不会 | 不会（永远绿） |
| socket 真死（RST） | 立即 | 立即 |

所以缺陷不在「注销得慢」，而在**注销之后那句「他还在线」没人收回**。

## 决策

1. **连接断了就作废「最近活跃」**（`hub.forget`）：断线是比 60 秒窗口**更硬的证据**，
   硬证据优先。`tables.connectionClosed(userId)` 负责这条策略，并广播让各桌立刻重算。
   代价：一次瞬断（切 WiFi、地铁进隧道）会让那颗点闪一下灰，浏览器几秒内自动重连、
   重连即重新注册并广播 —— 拿到的是一个短暂闪烁，换掉了「走了一分钟还显示在线」。
2. **只在「他一条连接都不剩」时作废**（`hub.hasAnyConnection`）：同一个人可能开着两个标签页、
   或两台设备。判据是**这个身份还有没有连接**，不是**这张桌还有没有连接** ——
   在线的判定本来就是身份级的（`CONTEXT.md` 的 **在线**），所以他在 A 桌坐着、另开一个标签页看 B 桌时，
   关掉 A 那个标签页不该让他在 A 桌闪成离线。这条由 `mcp-check` 的离线守卫专门钉住（见下）。
3. **注销函数变成幂等的、并返回「这是不是他的最后一条连接」**（`hub.register`）：它以前可以被调用两次
   而把计数减穿，那样「还有别的标签页」会被误判成「人走了」。
4. **写失败也走收尾**：SSE 的收尾以前只在客户端 abort 时发生，写不出去（`enqueue` 抛错）只把自己标成
   `closed`、**不注销** —— 那条死连接会永远留在连接表里，既是假在线，还会被后续每一次广播反复刷新
   （广播会给每一条注册中的连接重算负载，而重算会 `touch` 它的主人 ⇒ 窗口永远不过期）。
   现在 `stream` 只剩一条收尾路径 `cleanup()`：abort 与写失败都进去，幂等。

## 后果

- **关标签页/浏览器崩溃 → 立刻变灰**（实测 10~15ms）。用户的可见行为从这个改动里唯一的变化就是：
  以前要等将近一分钟，现在立刻。
- **半开连接仍然不会被发现**（拔网线、休眠、卡死但 socket 没死）：这一条**本次不修**。
  要修得加应用层存活检查（客户端定期 ack、服务端 N 秒收不到就注销），而 `EventSource` 不能发消息，
  得把客户端换成 fetch 流 + 定期轻量 POST —— 那是动客户端与协议的成本，只有当仓库真要做
  「掉线托管/计时/踢人」时才值得。相关的内核级缓解（`socket.setKeepAlive`）也只能把「内核判死」
  从十几分钟缩到一两分钟，且仍需上面那件事才能反映到那颗点上。
- **MCP 座位不受影响**：它没有 SSE 连接可断，照旧靠请求说话（ADR-0010 的原意）。
  所以「停手之后绿点不会自动转灰」这条已知保留（ADR-0012）仍然成立。

## 守卫

- `apps/web/test/presence.test.ts`：`forget` 清掉窗口并如实回报「是否真的清掉了」（别白广播一轮）；
  连接计数告诉你「这是不是最后一条」；注销函数**幂等**（重复调用不会把计数减穿）；身份之间互不干扰。
- `packages/mcp/scripts/mcp-check.ts` 的**离线守卫**（真服务器 + 真 SSE 流，两条传输各一遍）：
  其一，断开后**3 秒内**必须变灰（旧行为要 60 秒 ⇒ 会红）；其二，他**还有别的连接**（另一张桌的流）时，
  断开这张桌的流**不许**判成离线，两条都断了才变灰。
  这条守卫必须自己「保持热」：观察者从 t=0 起持续轮询 —— 否则它自己的第一次请求会触发一次广播，
  给那条（已死的）连接的主人续上窗口，量到的就是假象（第一版探针正是这么被骗过去的）。
- 两处断言都按 AGENTS 规则 9 做了「注入 → 变红 → 逐字节还原（sha256 比对）」：
  把 `connectionClosed` 改成空操作 ⇒ 第一条红；改成「不看还有没有别的连接」⇒ 第二条红。
